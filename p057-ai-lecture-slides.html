AIツールの変遷
AIツール 3つの時代
  • 第1世代: Chat時代（2022〜）
  • 第2世代: ワークフロー構築ツール時代（2023〜）
  • 第3世代: AIエージェント時代（2025〜）
  • わずか3年で大きく変化した
AIツールの変遷 — 第1世代
第1世代: Chat時代 — 対話型AIの始まり
  • ChatGPT（2022年11月）が火付け役
  • Claude — Anthropic社の対話AI。安全性と長文理解に強み。現在ChatGPTと並ぶ主力ツール
  • できること: 質問応答、文章作成、翻訳、要約
  • 限界: 人間が1回ずつ指示を出す必要がある
AIツールの変遷 — 第1世代
Chat時代 — ビジネスの現場では
  • 主な用途: メール下書き、議事録要約、翻訳、情報の整理
  • 期待: 「ホワイトカラーの仕事がAIに置き換わる」と言われた
  • 実態: 個人の作業効率は上がったが、業務プロセス全体は変わらなかった
  • 課題: 1回ずつ人間が指示する必要があり、大量の定型業務には向かなかった
AIツールの変遷 — 第2世代
第2世代: ワークフロー構築ツール時代
主なツール
  • Dify / Make — アプリ間をつなぐローコード/ノーコードツール
  • Notion AI — ドキュメント内でAIを活用
実態
  • 当時の期待: 複数アプリをAIでつないで業務自動化
  • 現実: コスト高 + 各アプリが自社AI機能を内蔵し始めた
AIツールの変遷 — 第2世代
Workflow時代 — ビジネスの現場では
  • 主な用途: CRMの更新 → メール自動送信 → スプレッドシートに記録、のような連携
  • 期待: 「ノーコードで業務自動化が誰でもできる」と注目された
  • 実態: 初期構築はできても、保守・運用コストが想定以上に膨らんだ
  • 課題: ツール間の接続が壊れやすく、エラー対応に専門知識が必要だった
AIツールの変遷 — 第2世代
ワークフローツールが縮小した理由
  • 各アプリが自社でAI機能を実装し始めた
  • 外部ツールで「つなぐ」必要性が低下した
  • 運用コストの高さがボトルネックになった
  • Dify/Makeは消えてはいないが、主流ではなくなった
AIツールの変遷 — 第3世代
第3世代: AIエージェント時代
  • Claude Code / Codex（開発者向けAIツール）— AIが自律的にコードを書き、タスクを実行する
  • 人間は「ゴール」を伝えるだけでよい
  • AIが計画 → 実行 → 検証まで一気通貫で行う
  • 2025年〜、実用化が始まっている
AIツールの変遷 — 第3世代
Agent時代 — ビジネスの現場では
  • 主な用途: コード生成、ドキュメント作成、データ分析の自動化
  • 期待: 「AIエージェントがワークフロー全体を担う」という構想が広がっている
  • 実態: ツールを作る能力は高いが、クライアント成果物の品質保証は別問題
  • ここに今日のテーマ「AIに自動化ツールを作らせる」の考え方が出てくる
AIツールの変遷 — まとめ
3世代の整理 — 何が変わったのか
  • Chat時代 — 人間が1回ずつ指示 → AIが1回答える
  • Workflow時代 — 人間が事前にフローを設計 → AIが決まった手順を実行
  • Agent時代 — 人間がゴールを伝える → AIが自律的に完遂
  • 共通課題: どの時代も「AIをどう業務に組み込むか」が問われた
実務でAIをどう使うか
ではビジネス現場でどう使えばいいのか
  • ツールの進化は分かった。では、実際のビジネス現場ではどう使えばいいのか。
  • ここからが今日一番伝えたいことです。
よくある誤解: 「AIで自動生成 = 業務改善」？
  • AIに議事録を書かせる、メールを生成する、レポートを作らせる...
  • それ自体は便利ですが、業務改善ではありません
  • なぜか？ — 業務フロー全体を見ていないからです
コアメッセージ
現実①: 業務フローの改善が大前提
  • AIを入れる前に、まず業務の流れを整理します
  • どこに無駄があるか、どこで人が詰まっているかを把握します
  • フローが悪いままAIを載せても、余計に混乱を招くだけです
  • BPOの現場で最も重要なのはこの工程です
コアメッセージ
現実②: フローの中の「自動化できるポイント」を洗い出す
自動化に向くもの
  • 繰り返し作業
  • 計算処理
  • 定型フォーマット出力
  • データ転記
人間が担うべきもの
  • 判断が必要な承認
  • 例外対応
  • 対人コミュニケーション
  • 例: 定型帳票の作成・送信 → 計算もフォーマットも毎月同じ → 自動化の好適対象
コアメッセージ
重要な指摘: なぜAIをフローに直接入れないのか
  • LLM（大規模言語モデル）は出力に「揺れ」がある
  • 同じ指示でも、毎回微妙に違う結果になる
  • 自然言語で生成 → フォーマット・数値の一貫性を保証できない
  • クライアント成果物 = 毎回同じルールで確実に出力される必要がある
コアメッセージ
クライアント成果物に求められる品質
AI直接生成の問題
  • フォーマットのブレ
  • 数値の丸め誤差
  • 項目の抜け漏れ
  • 毎回の確認・修正コストが発生 → 自動化の意味が薄れる
求められる品質
  • 同じ入力 → 同じ出力（決定的な処理）
  • 計算は1円単位で正確
  • レイアウトは完全に統一
コアメッセージ
正しいアプローチ: AIに「自動化ツール」を作らせる
  • AIがフローに介在するのではありません
  • フローを自動化するプログラム（GAS等）を、AIに書かせます
  • プログラムは同じ入力に対して常に同じ出力を返します
  • AIの役割 = ツールを作る職人。実行するのはプログラムです
コアメッセージ — まとめ
実務で通用するAI業務改善
  • Step 1. 業務フローを整理・改善する
  • Step 2. 自動化できるポイントを特定する
  • Step 3. 自動化ツール（GAS等）をAIに作らせる
  • Step 4. ツールが正確に繰り返し実行

今日のツール

ツール選択
なぜGoogle製品か
  • 変遷で紹介したDify等のワークフローツールもありますが、実務ではクライアントの環境に合わせて最適なツールを選びます
  • 企業のIT基盤は大きく2系統: Microsoft 365 / Google Workspace
  • 今回の架空クライアント（S社）はGoogle Workspace利用企業です
  • → Google製品（Gemini / GAS / Google Gemini のカスタムGem）で統一します
ツール選択
今日使う3つのツール — 役割の切り分け
  • Google Gemini のカスタムGem — 事前設定した情報とプロンプトを元に回答する専用AIチャットボット
  • Gemini — Google製のAI。今日はGASコードを書かせるために使う
  • GAS（Google Apps Script）— Googleサービスをプログラムで自動操作するツール
  • 3つの役割は明確に異なります。混同しないようにしましょう
Hands-on
ハンズオン: 午後ワークの予行演習
  • Phase 1: Gemini Gemで顧客bot体験
  • Phase 2: ヒアリングで課題発見
  • Phase 3: GeminiでGASコード生成
ハンズオン — 背景
S社（株式会社S）の紹介
  • SNSマーケティング支援企業（社員25名 + 業務委託者約40名）
  • 経理担当: 佐藤あゆみさん（ひとり経理 + 総務兼任）
  • 佐藤さんは複数の業務を抱えています。何が課題かはヒアリングで引き出してください
  • 皆さんは「業務改善コンサルタント」として課題解決に取り組む
ハンズオン — 用語
知っておきたい用語（経理の基礎知識）
経理用語
  • 業務委託 — 正社員ではなく外部専門家への発注契約
  • 支払通知書 — 業務委託者への「給与明細」に相当する書類
  • 源泉徴収 — 報酬から所得税を先に差し引く仕組み（税率10.21%、報酬100万円以下の場合）
ツール用語
  • インボイス制度 — 2023年開始。登録番号の有無で通知書の形式が変わる
  • GAS — Googleサービスをプログラムで自動操作するツール
  • Gem（カスタムGem） — 事前設定した情報とペルソナを元に回答する専用AIチャットボット
Phase 1
Gemini Gemで顧客botを触ってみる
  • 1スライド下部のQRコード、またはチャットで共有されたGemini GemのリンクをGeminiアプリで開く
  • 2チャット欄に質問を入力 → 佐藤さん（bot）が回答
  • 3試してみよう: 「普段のお仕事を教えてください」
  • !Gemの特徴: 設定した情報とペルソナの範囲で回答します（サジェスト質問なし・自分で考える）
Phase 2
ヒアリングで課題を引き出しましょう
  • 1顧客bot（佐藤さん）に質問して、業務の実態と課題を聞き出してください
  • 2どのような質問をすれば核心に迫れるか、チームで相談しながら進めましょう
  • 3聞き出した内容をもとに、課題を整理し、改善のねらいどころを定義してください
  • !午前の講義で学んだ「業務フロー → 自動化ポイント」の考え方を活かしましょう
Phase 3
AIを使って自動化ツールを作りましょう
  • 1Phase 2で特定した課題に対して、どう自動化するかをチームで設計してください
  • 2Geminiにプロンプト（= AIへの指示文）を投げて、GASコードを生成させましょう
  • 3どんなプロンプトを書けば正しいコードが返ってくるか、試行錯誤してみてください
  • !講義で伝えた通り、AIの役割は「ツールを作る職人」です。完成したツールが正確に動くかを検証しましょう
