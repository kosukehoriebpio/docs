security-audit プラグイン 使い方マニュアル

v0.1.3 — 社内 Claude Code ユーザー向け（非公開）

このプラグインでできること

  • Claude Code リポジトリのセキュリティを 4カテゴリ・0〜100点 で自動スコアリング
  • APIキー・シークレットの漏洩、Claude Code 固有リスク（CVE）、GitHub Actions の設定ミスを検出
  • スキャン後に 優先度順の修正アクションプラン を自動生成
  • Python のみで動作（外部ツール任意）。インストール済みなら /security-audit の一言で完結

概要

このプラグインは、Claude Code を使う社内メンバーのリポジトリが安全に保たれているかを自動チェックするツールです。開発者が気づきにくいセキュリティリスクを定期的に可視化し、重大な漏洩が起きる前に対処できるようにします。

使い方

基本（インストール済みの場合）

監査対象のリポジトリで Claude Code を開き、入力するだけです。

/security-audit
フルスキャン（スキャン + レポート生成）が実行されます。通常はこれだけで OK です。

コマンド動作用途

S 95-100優秀: 検出なし or Low のみ定期監査を継続

F 0-29深刻: 広範な侵害リスク緊急対応・堀江に相談

減点の仕組み

severity重み基準
Critical-10点即時の情報漏洩・RCE リスク
High-5点重大なリスクだが追加条件が必要
Medium-2点実際の悪用には複数の前提が必要
Low-0.5点ベストプラクティス違反
カテゴリごとに減点の上限があります（A:最大40点、B:25点、C:20点、D:15点）。1カテゴリに問題が集中しても他カテゴリの点数は守られます。

スキャン内容（4カテゴリ）

カテゴリ A — シークレット・APIキー漏洩（最大40点減点）

コード・設定ファイル・git 履歴からシークレットを検出します。

検出対象例
Anthropic API キーsk-ant-...
OpenAI API キーsk-...
AWS 認証情報アクセスキー・シークレット
GitHub PAT / Fine-grained tokenghp_... / github_pat_...
Slack / Notion / Stripe など合計16パターン
.gitignore の必須エントリ確認.env が除外されているか等

カテゴリ B — Claude Code 固有リスク（最大25点減点）

Claude Code 特有の攻撃ベクターをチェックします。

チェック項目リスク
apiUrl の不審な overrideCVE-2025-59536: 通信を中継・傍受される
hooks への shell injection悪意のあるコードの自動実行
MCP の不審なエンドポイントCVE-2025-52882: 外部サーバーへの情報送信
権限ワイルドカード（*）意図しないコマンド実行を許可
会話履歴へのシークレット混入~/.claude/projects/ 内のシークレット

カテゴリ C — GitHub 連携リスク（最大20点減点）

チェック項目リスク
Actions の SHA 非ピン留めサードパーティ Actions の改ざん攻撃
pull_request_target の誤用外部 PR からのシークレット窃取
リポジトリの public 化リスク意図しない公開設定

カテゴリ D — 依存パッケージ脆弱性（最大15点減点）

npm audit / pip-audit で既知 CVE を検出します。ツール未インストール時はスキップされます。

インストール手順

事前準備: GitHubリポジトリ（BPIOLMS/claude-security-audit）へのアクセス権限が必要です。
堀江（kosuke.horie@sevenrich.jp）にGitHubユーザー名を伝えて招待を申請してください。

Step 1: サブモジュールとして追加

git submodule add https://github.com/BPIOLMS/claude-security-audit.git plugins/security-audit

Step 2: SKILL.md を Claude Code に登録

mkdir -p .claude/skills/security-audit cp plugins/security-audit/skills/security-audit/SKILL.md .claude/skills/security-audit/SKILL.md

Step 3: コミット

git add .gitmodules plugins/security-audit .claude/skills/security-audit git commit -m "system: add security-audit plugin"

別マシンへのクローン時

# 新規クローン git clone --recurse-submodules <your-repo-url> # 既存クローンに後から追加 git submodule update --init --recursive

プラグインの更新

git submodule update --remote plugins/security-audit cp plugins/security-audit/skills/security-audit/SKILL.md .claude/skills/security-audit/SKILL.md git add plugins/security-audit .claude/skills/security-audit git commit -m "system: update security-audit plugin"

Allowlist（誤検知・意図的許容の除外）

テスト用フィクスチャや意図的に許容するリスクは、.security-audit-allowlist.yml をリポジトリルートに置くことで除外できます。

allowlist: - fingerprint: "abc123def456789a" # スキャン結果に表示される16文字の hex reason: "テスト用フィクスチャ（本番には存在しない）" expires_at: "2026-12-31" # 推奨: 定期的な見直しを促す
方針:
  • allowlist は「誤検知」または「意図的に許容するリスク」のみに使う
  • Critical は expires_at を必須とする
  • 定期的に棚卸しし、不要なエントリは削除する
