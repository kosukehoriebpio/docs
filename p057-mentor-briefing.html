メンターの役割

フェーズごとに関わり方が異なります。基本姿勢は「学生の自走を促す」こと。

10:00-11:50 オープニング〜AI講義

基本姿勢: 静観。学生の反応を観察する時間です。

  • 接続確認を補助し、学生の入室状況・第一印象をメモ
  • AI講義中は未経験者(Lv1)のフォローに注力
  • ハンズオンで操作に詰まっている学生がいたら操作方法だけサポート
  • 学生の自己紹介での発言内容・コミュニケーション姿勢を観察
12:35-14:20 ヒアリング・設計フェーズ（最重要）

基本姿勢: 観察重視。学生がNotebookLMで「Aさんbot」にどう質問するかを観察します。

  • 質問テンプレートは意図的に提供していません（質問力を評価するため）
  • 困っている学生にはNotebookLMの操作方法だけ助ける
  • 内容のヒント（「こう聞いてみたら？」等）は出さない
  • 思考の整理を手助け: 「それ、もう少し具体的にすると？」程度のファシリテーション
  • チームの課題構造化・仮説の質・役割分担を観察し、Snapshot 1に備える
14:35-16:20 GAS開発フェーズ

基本姿勢: 技術サポート。学生の自力解決を優先しつつ、適切なタイミングでヒントを出します。

  • エラーが出たらまず学生自身にエラーメッセージを読ませる（学習機会）
  • 5分以上詰まったらヒントを提供
  • Geminiの使い方を教えるのはOK（「プロンプトにエラーメッセージを貼って聞いてみて」等）
  • 15:30のSnapshot 2で進捗を評価し、未完成チームにはフォールバック切替を案内
16:20-17:40 プレゼンフェーズ

基本姿勢: 評価シート記入に集中。質問は堀江が主導します。

  • 発表準備では構成アドバイス（時間配分・デモ手順）と画面共有テストを支援
  • 最終発表中はSnapshot 3の記入に集中
  • 質疑は堀江が主導するが、メンターからの質問も可
全セッション共通 Snapshotメモ

計3回、所定のタイミングで各学生について記録します。

  • 記録形式: Strong / Neutral / Concern の3値 + 具体的行動メモ1行
  • 例: 「Strong — Aさんの心理的負荷まで言語化し、チームに共有していた」
  • 例: 「Concern — 他メンバーの発言を遮り、自分の意見だけ進めていた」
  • キーワードだけのメモでもOK。詳細は終了後に記入

評価ガイド

評価は2つのレイヤーで構成されています。Layer 1はチーム発表の点数評価、Layer 2は個人の定性観察です。

Layer 1: コンテスト評価（チーム発表評価）— 100点満点

配点: 観点A 40点 + 観点B 40点 + 観点C 20点

観点A: 課題の捕らえ方（40点）

ヒアリングで表面的な「作業時間が長い」を超え、心理的負荷・機会損失など2次課題まで言語化できているか。数値で削減効果を示せているか。

観点B: 改善の実装度（動いたか）（40点）

GASが正常動作し、6件全員分のPDF生成・Gmail送信デモを完遍したか。金額計算（源泉=floor(A*0.1021)、差引=A+消費税+交通費-源泉）が正確か。

観点C: デモの完成度・ストーリー（20点）

Aさんの声 → ツール選定理由 → ライブデモ → 導入前後比較のストーリーが明確か。非エンジニアの審査員にも伝わるか。

4段階スケール: Lv4卓越（36-40/18-20点）、Lv3十分（28-35/13-17点）、Lv2基礎（16-27/7-12点）、Lv1未到達（0-15/0-6点）。各観点に具体的な到達記述があり、「何ができていれば何点」が明確に定義されています。

Layer 2: 個人見極め評価（スナップショット観察）— 定性評価

点数化せず、4観点 x Lv1-4の定性評価。総合判定は「Lv3以上が何観点あるか」「Lv1があるか」で行います。

観点(1): ヒアリングの深さ（共感・課題発見力）

Aさんの心理的負荷まで言語化できたか。課題を「作業問題」でなく「人の問題」として捕らえているか。

観点(2): AIの使いこなし

プロンプトを3回以上反復改善し、条件（源泉計算式・6件マスタ・PDF出力形式）を自分で言語化してGeminiに伝えられたか。エラーからの原因推測 → 再プロンプトループを独力で回せたか。

観点(3): チーム協働

役割を明示・合意して進行し、詰まっている他メンバーを観察して自発的にサポートしたか。意見の相違を建設的に調整できたか。

観点(4): つまずいた時の粘り

2回以上の詰まり局面で代替手段（別プロンプト・部分実装・スコープ縮小）を提案・実行したか。振り返りで「こうすれば乗り越えられた」と言語化できたか。

レベル基準: Lv4 = 自発的・主体的に行動し言語化もできている / Lv3 = 概ねできているが自発性や深さに不足 / Lv2 = 受動的で表層にとどまる / Lv1 = 行動・言語化がほぼ観察されない

Snapshotの書き方

評価 意味 記入例
Strong 期待を上回る行動が観察された Aさんの心理的負荷まで言語化し、チームに共有していた
Neutral 標準的な行動 指示された作業は遂行。自発的な提案は見られず
Concern 懸念が残る行動が観察された 他メンバーの発言を遮り、自分の意見だけで進めていた

選考判断基準

区分 条件
優先案内（特別ルート） Layer1合計75点以上（観点A Lv3以上 かつ 観点B Lv2以上が必須）+ Layer2で4観点中3観点以上がLv3以上かつLv1がゼロ。例外昇格: Layer1が65-74点でもLayer2全観点Lv4、または観点(1)(4)が両方Lv4ならメンター協議で優先案内可。
通常ルート Layer1合計50-74点 + Layer2でLv1が1-2観点あってもLv3以上が2観点あれば可。
案内見送り Layer1合計49点以下（観点B Lv1=動作確認ゼロかつ他観点も低い場合）、またはLayer2で観点(3)チーム協働がLv1かつ複数観点にLv1がある場合。

当日の発言・行動ルール

  • NG 「早期選考に進めます」 → 確約は絶対にしない。選考判定は人事（堀江）が別途行う

  • OK NotebookLMの操作で困っていたら操作方法を教える
  • OK GASのエラー対応は学生に考えさせてからヒントを出す
  • OK 時間管理の声掛け（「あと10分です」等）

FAQ / トラブルシューティング

Q. NotebookLMが応答しない
ページリロードを試す。それでも復旧しない場合は講師（堀江）に連絡してください。
Q. GASでエラーが出て学生が完全に止まった
まずエラーメッセージを学生自身に読ませてください。それでも5分以上詰まったら、一緒にデバッグに入ります。「Geminiにエラーメッセージを貼って聞いてみて」と促すのも有効です。
Q. 学生の進捗がバラバラ
早い学生にはボーナス課題を案内します（UIカスタマイズ、エラーハンドリング追加、追加機能の実装等）。遅い学生にはフォールバック提出物（設計書+プロンプト集+想定入出力+テストケース）への切り替えを15:30の実装チェック時に案内します。
Q. Google Meet接続不良
チャットで状況を確認してください。必要に応じて堀江に連絡。学生が再接続する場合は同じMeetリンクに再入室を案内します。3分以内に戻らない場合は緊急連絡先へ連絡。
Q. 学生がヒアリングで全然質問できていない
NotebookLMの使い方だけサポートしてください。「何を聞きたい？」と問いかけるのはOKです。ただし、具体的な質問の提示（「こう聞いてみたら？」）はNGです。質問力の評価が目的であることを念頭に置いてください。
Q. 評価シートの記入が追いつかない
Snapshotメモ（キーワードだけ）を優先してください。Strong / Neutral / Concern の3値だけでも記録があれば、詳細は終了後に記入できます。
